## Intent

**Problem:** Enabled MLB and MLS events do not accumulate immutable pregame moneyline and spread evidence, so the MVP cannot reproduce offered prices, comparison-book context, freshness gaps, or later CLV evaluation.

**Approach:** Add a provider-neutral, policy-governed odds collection workflow with a The Odds API HTTP adapter and synthetic fixtures, strict multi-sport normalization, a separate immutable odds store with monotonic current projections, and one bounded replay-safe worker contract shared by manual and disabled-by-default scheduled invocation.

## Boundaries & Constraints

**Always:** Resolve exact enabled odds coverage and registered markets before provider work; bind provider events through FTE-DATA-002 mappings to a still-pregame canonical event; normalize MLB two-way moneyline/run line and MLS three-way moneyline through stable participant-based selection keys; preserve provider and retrieval time provenance, offered and comparison books, partial/missing/stale/suspended/closed states, request quota, and redacted run telemetry; append immutable evidence with deterministic identities and advance current projections only by a total authority order; isolate leagues and checkpoint only durable pages.

**Block If:** A production bookmaker or sport key cannot be configured explicitly, or provider terms require storing/exposing licensed raw payloads. Missing Hard Rock or other offered-book coverage is an explicit unavailable state, not a reason to fabricate data.

**Never:** Scan the event table; synthesize pre-activation history; overwrite/delete immutable snapshots; infer canonical identity from labels; log API keys or raw licensed responses; activate production scheduling by default; calculate picks, place bets, ingest live/player-prop markets, or duplicate FTE-DATA-002 identity orchestration.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Enabled MLB | Mapped pregame event; `h2h` and `spreads` fixture books | Two-way participant selections and paired run-line selections persist with offered/comparison provenance | Invalid line/outcome structure rejects the provider batch without checkpoint advance |
| Enabled MLS | Mapped pregame event; `h2h` fixture | Participant/draw/participant selections persist as three-way moneyline | Missing or duplicate draw/participant outcome is explicit partial/invalid evidence |
| Exact replay | Same trusted response identity and normalized content | Immutable manifest/snapshots deduplicate and counters report duplicates | Same identity with different material is a durable conflict and no checkpoint advance |
| Older or suspended evidence | Valid out-of-order, suspended, or closed observation | Append history; current projection advances only when its authority tuple wins | Never delete or regress the current projection |
| Unsupported or partial | Policy/provider lacks market, book, or outcome | Persist bounded market-gap observation and run counters; no fabricated snapshot | Continue other events/markets in the league page |
| Unmapped or changed event | No exact mapping, changed version/start, or no longer pregame | Persist redacted gap/skip outcome; attach no odds | Retry only transient races; never guess identity |
| Provider failure | Rate limit, timeout, malformed body, or 5xx | Preserve prior checkpoint and durable request/quota audit; isolate league retry | Stable redacted error codes; raw body/key never logged |

## Design Notes

- FTE-SPORT-007 is complete and supplies downstream consensus compatibility; this story collects auditable inputs and does not persist consensus or picks. FTE-028 may later harden consensus and is not a blocker.
- Use a separate `FindTheEdgeOdds` table because immutable price evidence is a high-write workload. Retain snapshots without TTL for MVP; direct transactional snapshot/current writes are the MVP path, with stream rebuild deferred.
- Snapshot identity includes provider, canonical/provider event, book, market, stable selection, line, provider-time availability/value, and trusted retrieval/response identity. A manifest enumerates requested books/markets/outcomes so absence is evidence without creating a fake price.
- The Odds API V4 uses `baseball_mlb`, featured markets `h2h`/`spreads`, American format, and quota headers. MLS provider sport key and offered bookmaker keys remain explicit deploy configuration validated before enabling production; fixtures exercise the shared contract.
- This story consolidates the acquisition/persistence/job/quality scope duplicated by backlog FTE-014 and FTE-020–FTE-024. Completed FTE-DATA-002 and FTE-SPORT-007 remain authoritative dependencies.
- Dynamo page commits include exact mapping and canonical event version/status/start condition checks in the same transaction as immutable evidence, current projections, gaps, checkpoint, and run. Manifest rereads recover lost successful responses; material mismatches fail closed.
- Activation is an explicit deployment parameter, the collection schedule is independently disabled, and both manual and scheduled inputs enter the same strict command/policy path.
- Repair iteration 5 re-derives all production code from `986fdf6`: cross-table page commits must name the event table for canonical fences and the odds table for odds artifacts; every scheduled 15-minute poll owns a distinct cycle while continuations retain that cycle; quota reservations identify durable physical attempts; response material excludes retrieval/quota metadata; activation uses trusted worker time; page size is rejected before checkpointing when its safe worst-case transaction footprint exceeds DynamoDB limits; and all snapshots and canonical-linked gaps carry exact mapping/event fences.
- Convergence reset architecture deliberately removes all-page atomicity. The only atomic transitions are: (1) reserve one physical provider attempt and daily quota unit; (2) commit one bounded event plan with exact DATA002 mapping/canonical fences, immutable evidence/gaps, optional conditional CURRENT, and EventReceipt; (3) after verifying every ordered EventReceipt against the immutable PagePlan, write PageReceipt, CAS the exact checkpoint position, update receipt-derived cycle totals, and enqueue/record continuation intent. PagePlan is the sole recovery source; receipts are the sole completion evidence.
- Each event transaction preflights duplicate physical targets, operation count, item bytes, and aggregate bytes. Older authority appends evidence while omitting CURRENT; equal authority with equal material is replay; equal authority with different material is corruption; newer authority condition-checks the exact prior CURRENT. No reconciliation overwrites immutable rows.
- Attempts are keyed by cycle, execution ID, and invocation-local ordinal. A crash before a call can safely reuse the unconsumed reservation; an ambiguous/failed physical call is finalized truthfully and a later invocation reserves a new attempt. Failure audit timestamps come from trusted execution time, and accepted operational failures propagate to FIFO partial-batch retry.
- The provider adapter supplies roles and labels only. Canonical participant IDs/order come exclusively from strongly validated DATA002 mapping and event rows. Reliable provider states are preserved; otherwise returned valid prices are active and absent/ambiguous data becomes a bounded explicit gap.
